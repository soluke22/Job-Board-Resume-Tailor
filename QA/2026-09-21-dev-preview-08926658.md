## Defects

### Add Job loses its partial-success retry state

Severity: HIGH  
Workflow: Add Job + Analyze  
Reproduction: In Public Demo, enter a synthetic company/title/description and click Analyze Fit. Owner-only analysis fails. The job count increases by one and Job Detail replaces the modal. Reopening Add Job shows an empty creation form with Analyze Fit, not Retry analysis. A rapid double-click on a separate synthetic entry increased the count from four to five, not six.  
Expected: Keep the saved job selected and the modal/form context available; show `Job saved, but analysis failed. Retry analysis.` and a `Retry analysis` action bound to the same job ID without another creation.  
Observed: The modal disappeared before analysis failure was rendered. Job Detail showed an authorization banner and a separate Re-analyze control; the required partial-success message and modal retry were absent. Reopening Add Job offered a fresh creation form.  
Impact: A user cannot safely distinguish saved-but-unassessed from a failed creation at the entry point, and re-entering the posting could create a duplicate. The edited-fields-before-Retry edge case cannot be tested because that Retry UI never appears.  
Likely owner file/function: `src/context/AppContext.tsx` `addJob` (early `setCurrentView('job-detail')`) and `src/components/AddJobModal.tsx` `handleSubmit` / `pendingJobId`.  
Blocking production promotion: YES

### Unassessed Job Detail presents unsupported conclusions

Severity: HIGH  
Workflow: Add Job / Fit Analysis  
Reproduction: Open the newly saved synthetic job after the expected analysis authorization failure. No fit score, coverage, requirement matches, or assessment exists.  
Expected: Explicit Unassessed/Analysis pending state and no evidence-coverage or claim-support conclusion until assessment succeeds.  
Observed: Job Detail displayed `Verdict Borderline` and `Zero unsupported claims detected. All target requirements map to candidate evidence.` while the match table was empty. It also said assessment was required, but that did not neutralize the affirmative conclusions.  
Impact: May falsely reassure a candidate that an unanalyzed posting has been checked against evidence. No export/readiness bypass was observed, but the visible decision guidance is ungrounded.  
Likely owner file/function: `src/components/JobAnalysisView.tsx` default verdict (`fit?.verdict || 'Borderline'`) and empty withheld-claims message.  
Blocking production promotion: YES

### Malformed Search Preferences JSON implies a durable save failure

Severity: MEDIUM  
Workflow: Search Preferences  
Reproduction: In Public Demo Setup, replace preferences JSON with `{ invalid json` and click Save search preferences.  
Expected: Visible local validation error; dirty/editable draft; unchanged canonical preferences; no reload-required message because persistence was never attempted.  
Observed: The JSON parse error appeared, but the status simultaneously said `Not saved — reload required`. Restoring valid synthetic JSON and saving then succeeded; the canonical values survived reload.  
Impact: Misleading recovery instruction for a local input error, without observed data corruption.  
Likely owner file/function: `src/components/CandidateSetupView.tsx` Search Preferences save catch / `preferencesSaveState`.  
Blocking production promotion: NO
